# 超级工作群实施合同与分工

日期：2026-09-05。基线：本地 v2.2.16 合并提交 fe40cf7993。用户已授权按此轮沟通并行实施。

## 必须保持的产品规则

1. LobeHub 为唯一后台，优先复用现有群聊、消息、话题、成员与管理界面。
2. 每个用户（含管理员）默认一个自己的超级工作群；统一助理结构，用户聊天数据独立。
   - 普通登录默认进入当前账号自己的超级工作群并恢复最近话题；官网头像不再把当前资讯/案例页当作登录后的落点。明确邀请或指定操作的安全返回地址仍保留；新账号完成既有引导后进入自己的群。
3. 管理员统一添加/调整助理，现有用户及之后注册用户同步结构。30–100 个助理是容量目标，不虚构助理内容。
4. 普通用户不能添加或删除助理；点击助理仅查看介绍，不能私聊，可在群里 @。
5. 最近话题自动展示 10 条，点击定位对应群聊天记录；超过仅隐藏最早入口，历史不删，用户不能删话题。
6. 自己的默认群不可退出/删除，其会话和聊天记录永久保留；不因本轮改造删除已有其他群或历史数据。
7. 群主可邀请其他用户，对方接受后加入；群主可以踢出真人成员。用户自由退出别人的群。
8. 退出/被踢后清除该用户对应会话、缓存与访问权，群主及其他成员记录保留；重新加入不能绕过先前历史清除。
9. 会话显示自己的超级群和已加入的“XXX用户的群组”。群顶部“…”展开真人/助理成员列表、头像和名称。
10. 移动端面板可滚动，长名字、介绍、30–100 个助理不导致横向挤压；保留桌面既有布局。
11. 默认超级群必须包含“旅游群主AI”协调助理；复用固定 supervisor 身份，成员列表不可用当前用户替代或隐藏它，不重复创建第二个群主助理。
12. 旅游群主重点负责协作架构、职责分工与讨论秩序，协调意见分歧避免争吵；这是工作职责，不增加自行改群结构、增删助理、踢人、删历史的权限。
13. 最新计费规则：默认个人超级群的实际模型 Token 消耗自动计入群归属账号，无需群代付开关、成员额度或周期配置。保留既有用量定价、余额预留、幂等结算和退款保护；真实发起成员保留在 hosted run 审计，资金预算归群主账号。不执行真实收费验收。

## 本轮续做分工

- A：旧账号旅游群主空介绍/旧默认职责的安全回填，接通 ready 与 owned getGroupDetail 直达入口；独占 user service、agentGroup 相邻路由与回归。
- B：隔离 PGlite 的双用户完整邀请、退出/踢出、重入历史边界回归；定稿后独立审查 A/C 新增量。不操作真实用户。
- C：窄视口超级群复用现有 mobile Layout/Header，NavPanel 仅 group 不占桌面侧栏宽度；成员头像 fallback。独占对应布局和组件测试。
- 主线程：统一桌面/窄窗口/手机镜像验收、双账号前置与结果记录。仅此前已获准的重启完成，不再擅自重启；保留手机草稿。
