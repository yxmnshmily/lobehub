# 通知接入

站内通知复用 `notifications` 和 `notification_deliveries`，个人与工作区按现有接口隔离。通知设置位于 `/settings/notification`，支持 `inbox`、`email`、`sms` 子页，按当前登录账号保存。邮箱、手机号只能使用已验证的账号信息，不能在通知接口中指定他人地址。

已接入 26 种真实事件，通知中心、分类计数及站内/邮件/短信的独立开关共用同一份事件目录：

- 账单：积分余额低于 10 万、积分耗尽、充值到账、账务调整、积分退回。
- 生成：图片和视频生成成功、失败。
- Agent：助理任务完成、失败；手动任务的本轮运行结束、失败（不等同于整个任务完成）。
- 待处理：助理等待确认、任务分配、资源移交待确认。
- 定时任务：计划任务成功、失败。
- 工作区动态：任务评论、话题评论/回复、资源移交接受/拒绝。
- 提及：任务和话题评论中提及你。
- 系统消息：自己的评论被移除、恢复。

评论接收人沿用业务权限过滤，跳过作者并按用户去重；同一评论既回复又提及时只发提及通知。资源移交通知关联现有待处理卡片，避免重复计数。助理确认通知只用于返回会话，不生成审批令牌；审批权限仍由会话校验。通知内容不复制私人评论、运行参数或提供商原始错误。

事件的用户、工作区及去重键由服务端业务提供。站内通知默认开启，邮件与短信默认关闭；不补发历史消息，也不伪造订阅事件。收件箱开启时仍会保留邮件/短信发送失败对应的站内消息。

## 积分账务

充值到账只在在线支付验签、金额校验及入账事务提交后，或管理员充值流水提交后通知。积分消耗完毕只在真实用量扣费后余额归零时通知，覆盖普通预留结算、历史调用结算与群组代付结算；预留额度、下单、余额查询不会生成耗尽通知。上述消息归入“账单”，以账务流水 ID 去重，发送给实际积分账户所有者的个人收件箱。三个渠道均可单独关闭每类消息。管理员调整、冲正和注册赠送不冒充充值。余额预警仅在真实扣费使余额从不低于 10 万首次跌到 10 万以下且仍大于零时产生；持续低余额扣费不重复预警。非零管理员调整使用“账务调整”，正向冲正使用“积分退回”，不冒充现金退款。

## 邮件

复用现有 `EMAIL_SERVICE_PROVIDER`（SMTP 或 Resend）配置。设置页只有在服务配置齐全且邮箱验证后允许启用。邮件仅包含通知类别和登录查看提示，不外发提示词或模型回复。

## 短信

复用腾讯云短信凭据和签名，新增独立变量 `TENCENTCLOUD_SMS_NOTIFICATION_TEMPLATE_ID`。不能填写验证码模板 ID。

模板应通过腾讯云审核，接受 **1 个参数：通知类型名称**。例如模板正文可为“您有一条{1}通知，请登录平台查看详情。”（最终以审核通过的文案为准）。当前等待用户补充模板 ID / 正文；如果审核模板参数不同，按实际模板调整 `channels.ts` 中的参数映射。配置后重启后端，再从通知设置开启短信。

## 发送记录与边界

同一用户、工作区、类型、事件 ID 只创建一次记录；重复业务回调不会重复发信。发送结果保存为 sent/failed，设置页可查看最近 10 条邮件/短信记录。失败不会自动重发，避免供应商结果不明确时重复收费；提供商返回成功表示已受理，并不代表收件人最终收到。没有配置短信模板时不调用短信供应商。

验证命令：`TEST_SERVER_DB=0 ./node_modules/.bin/vitest run apps/server/src/services/notification/*.test.ts`。这些测试使用临时内存数据库及模拟供应商，不向真实用户发送通知。
